# Agnes Image 2.5 Flash

模型 ID：`agnes-image-2.5-flash`。支持文生图、图生图（转换/重绘/风格化）和多图合成；结果可按 URL 或 Base64 返回。

## 端点与认证

- 创建：`POST /v1/images/generations`
- 认证：`Authorization: Bearer <AGNES_API_KEY>`
- 配置：环境变量或 `.env` 中的 `AGNES_API_KEY`、`AGNES_BASE_URL`，默认 `https://apihub.agnes-ai.com/v1`。
- 运行环境：Python 3.10+，仅用标准库、无第三方依赖；脚本与共享模块同目录，`python examples/<脚本>.py` 直接运行。

## 请求字段

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `model` | string | 是 | 固定 `agnes-image-2.5-flash` |
| `prompt` | string | 是 | 生成或编辑指令 |
| `size` | string | 是 | 档位 `1K`/`2K`/`3K`/`4K`；技能默认 `1K`；也兼容历史精确尺寸写法 |
| `ratio` | string | 否 | 与档位配合的宽高比；技能默认 `16:9`（接口默认 `1:1`） |
| `return_base64` | boolean | 否 | 文生图以 Base64 返回时使用 |
| `extra_body.image` | string[] | 图生图/合成必填 | 输入图像数组，公共 URL 或 Data URI Base64 |
| `extra_body.response_format` | string | 否 | `url` 或 `b64_json`；不要放在顶层 |

支持比例：`1:1`、`3:4`、`4:3`、`16:9`、`9:16`、`2:3`、`3:2`、`21:9`。

## 输入素材

- 图像输入放在 `extra_body.image`（数组），不要传顶层 `image`，也不需要 `tags: ["img2img"]`。
- 公共 HTTPS URL、Data URI Base64、本地文件路径均可；本地文件由 `examples/media_input.py` 读成 Data URI 内联。该端点官方明确接受 Data URI 输入。
- 输入 URL 必须公开可访问，不需要登录/Cookie；无法公开访问时改用 Data URI。

## 输出读取

- URL 输出：`data[0].url`
- Base64 输出：`data[0].b64_json`
- 文生图可用 `return_base64: true`；图生图用 `extra_body.response_format: "b64_json"`。

## 提示词规范

### 准备原则

- 提交前先重写并补全：在用户原意之上叠加场景、光照、材质、构图、镜头与可见细节；保留全部明确要素，不增用户未要求的主体或风格。
- 不堆砌负面 / 禁止词：本接口官方模板不含 negative prompt，长串"禁止、避免"会干扰语义对齐；想要的效果优先用正面的具体可见细节描述，硬性排除只写短句。
- 提示词只引导生成方向，不保证逐像素还原；反复微调仍是同一结果时，属模型能力上限，应如实告知用户。

### 人像与去 AI 味

- 皮肤写真实细节：自然肤色微差、细微瑕疵、真实纹理；五官与身形保持自然，不做蜡像式完美对称；肢体结构完整，手指数量清晰可数、不粘连融合，四肢与双脚完整，持物 / 托腮的手自然不遮挡五官。
- 硬性排除只写短句：不缺指 / 多指、不断手断脚、不缺脚、不让身体只画一半（全身入画时头到脚完整）；脸部对焦清晰不模糊，双眼处于同一水平线、大小一致、瞳孔居中、视线方向一致，不眼歪、大小眼、五官错位，不多余肢体。
- 年轻主体不要写"皱纹、细纹清晰可见"（容易被渲染成老人脸）；不要写"油润高光、细腻光泽过渡"（容易出油光脸），改用自然散射光与局部、非均匀的皮肤细节描述。
- 特写近景才看得出皮肤细节，远景会掩盖；需要细节丰富时补"高视觉密度、真实照片级细节"。
- 多图合成先锚定主体身份（五官、服装、场景），再说明每张参考图承担的角色或质感，避免主体被参考图替换。
- 构图写实类略带随手拍摄的自然感，避免死板居中与摆拍感；材质、布料、金属、木材等表面质感写具体。

### 文生图

按顺序描述：`[主体] + [场景/环境] + [风格] + [光照] + [构图] + [质量要求]`。

画面信息密度高时，写清视觉层次：主要主体、背景环境、次要细节、风格、光照与构图约束，而不是只堆形容词。

### 图生图

按顺序描述：`[改变要求] + [新风格/场景] + [需要添加或移除的元素] + [需要保留的元素]`。

先点明要改什么，再写出必须保留的部分，例如原始构图、主体布局或产品外形。

### 多图合成

按顺序描述：`[参考图角色] + [目标场景] + [图像之间的关系] + [风格/光照/构图]`。

明确每张参考图分别承担什么角色（如主角色、产品参考），以及最终画面如何把它们组合到一起。

### 构图、镜头与布局

- **景别与机位**：按主体选择特写 / 半身 / 全身 / 全景；机位写明平视 / 俯拍 / 仰拍 / 过肩；焦距可选 50mm 标准、85mm 人像或广角；焦点落在主体上，背景按需要虚化或保持真实清晰。
- **画面布局**：写清前景、中景、背景层次；留白位置与用途（如顶部留标题位、右下留白）；网格类画面注明"N 行 N 列"。
- **媒介与光影**：标明媒介类型（写实摄影 / 3D 渲染 / 水彩 / 胶片摄影 / 插画等），写实类写明真实照片质感；材质写出布料、金属、木材、皮肤等具体表面；主光来自明确方向（侧前窗光 / 夕阳逆光 / 顶光 / 机顶闪等）并注明色温倾向；主色与辅色搭配自然、不过饱和；按需要补细腻颗粒或自然动态范围。

### 画面文字与数据标注

- 需要画面文字时，逐字写出文案，并标明字体风格（衬线 / 无衬线 / 手写 / 毛笔 / 宋体 / 黑体等）与位置；除指定文字外，不添加其他文字、字母或数字。不要用"一个带标语的牌子"这类占位说法。
- 数据类内容注明单位与时间范围；示例数据须标明"示例"。

## 示例脚本（`examples/`）

| 脚本 | 用途 | 参数 |
|---|---|---|
| `text-to-image.py` | 文生图（只回 URL） | `[提示词] [尺寸] [比例]` |
| `text-to-image-base64.py` | 文生图（Base64 直落盘） | `[提示词] [尺寸]` |
| `image-to-image.py` | 图生图（只回 URL） | `[输入图片路径或URL] [提示词] [尺寸] [比例]` |
| `multi-image-combine.py` | 多图合成（只回 URL） | `[图片1] [图片2] [提示词] [尺寸] [比例]` |
| `batch-images.py` | 批量并发生成 + 线程池下载 | `--request <json|-> [--concurrency N] [--output DIR] [--no-download]` |
| `download.py` | 独立下载进程（调度方后台拉起） | `<url> <out_dir> [index]` |

## 默认参数与交付顺序

- 用户未指定时：档位 `1K`、比例 `16:9`；用户显式给出的尺寸 / 比例以用户输入为准。
- 接口返回图片 URL 后，先把 URL 发到对话框展示；生成脚本不在进程内下载，由调度方另起独立 `download.py` 后台进程落盘，不阻塞回复；下载完成后再展示本地路径，下载失败单独提示。

## 批量生成与本地下载

- `batch-images.py` 读取 JSON 数组（每项为 `prompt`/`size`/`ratio`），线程池并发提交，默认最多 8 个并发，`--concurrency` 可覆盖；任务一完成先打印 URL，并立即进入下载池与其余生成并行，不阻塞 URL 交付。
- 下载由 `media_download.py` 完成：流式写入 `--output` 目录（默认 `output/batch-images`），单文件默认上限 512 MiB，瞬态错误有限重试；扩展名取 Content-Type，回退到 URL 后缀。
- `--no-download` 只返回 URL，不落盘。

## 错误处理与重试

- 可重试瞬态条件：网络/DNS/超时抖动，以及 HTTP 408、429、500、502、503、504；由 `examples/http_retry.py` 有限次重试（默认 3 次）。
- 退避优先读取响应头 `Retry-After`（上限 60 秒），否则指数退避（上限 30 秒）；429 在同一进程内跨线程共享冷却窗口。
- 不可重试：400 参数错误、401/403 鉴权失败、404 资源不存在等直接抛出 `HttpError`，不做重试。
- 错误按类别给出中文提示：鉴权失败、参数被拒、触发限流、服务端错误等；批量任务单条失败被隔离，不影响其他任务。
- 注意：创建请求在 5xx 后重试仍可能产生重复任务并计费；重试后请核对任务清单，避免重复提交。

## 常见问题

- `response_format` 必须放在 `extra_body` 内，顶层放置会被忽略。
- 图生图缺少 `extra_body.image` 会报错；不要传 `tags`。
- 不支持的精确尺寸可能被标准化；需要 16:9 高清素材时用 `2K` + `16:9`，下游再裁剪。
- 请求超时建议 60–360 秒。
